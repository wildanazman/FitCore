# Diet planner extension

Mode: Operate. Existing chalk/cobalt/Hanken system, code-led; no replacement identity or generated assets.

## Direction contract

THESIS: Turn the text checklist into a dated meal ledger. Planning never counts as intake; eating is an explicit action.

OWN-WORLD: Inherit DESIGN.md, flat meal rows, cobalt actions, legible labeled totals, 44px controls. No emojis.

STORY: Select a day, search local foods or adapt the existing example, set portions, compare planned nutrition with targets, log eaten meals once. Keep habits and consistency history.

CONTENT: Familiar Malaysian/Malay meals with explicit non-halal ingredients excluded from suggestions. No food-name-based halal certification. Template ingredients use point-form names with portions on a secondary line, both in the guide and weekly meal rows.

RELATED IMPORT: Paste-first ChatGPT nutrition review accepts explicit BM/English prose, lists, tables and JSON. Ranges use disclosed midpoints; missing macros remain blank and block saving. Ambiguous multiple foods require a meal total. Processing is local; no automatic ChatGPT request. Preserve the incumbent design files.

FIRST VIEWPORT: Page title, existing route switch, selected-week navigation and seven-day strip, planned versus eaten budget, then that day's meal rows and Add meal. Advanced approaches remain separate.

FORM: Local functional extension of the established weekly surface; no concept-seed required. Signature interaction is a planned meal becoming a linked food log without duplicate entry. Editing/copying never overwrites logs or existing plans.

FINISH: unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance
